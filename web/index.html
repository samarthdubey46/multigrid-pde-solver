Fine → coarse → fine: the multigrid correction

Fine grids smooth local errors. Coarser grids help correct broad errors. The CPU transfers the remaining mismatch down, solves the smallest system, then brings corrections back up.

64 → 22 → 8 → 3 (CPU) → 8 → 22 → 64

Three optical matrices: A₀, A₁, A₂. One active at a time. A₃ is a 3×3 solve inside the CPU. Each optical level gets 3 pre-smoothing and 3 post-smoothing sweeps.

What the CPU is doing

x
The full PDE solution estimate, updated after each PCG call.
r
Outer residual: b − A₀x. This is the right-hand side of A₀δ = r.
δ
The correction PCG is building. It starts at zero for each call.
s
Inner residual: r − A₀δ. Your Python calls this local variable r.
z
The V-cycle’s approximate solution to A₀z = s. PCG uses it to choose p.
α
The changing step size (sᵀz)/(pᵀq), with q = A₀p.
Why α comes after q

p chooses the direction of the next correction. q = A₀p tells the CPU how that direction affects the residual. Only then can it calculate α and update δ ← δ + αp and s ← s − αq. The two updates could run in parallel after α is ready; later V-cycle work must wait for the updated s.
