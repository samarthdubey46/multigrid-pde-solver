# Continuous loop council

Problem: show the complete iterative method and its hardware mapping in one continuous HTML flowchart, accessible to a professor new to the project.

Composition: Aristotle (structure), Ada (numerical invariants), Feynman (signal meaning). Protocol: independent delegated first round; peer cross-examination and final stances combined in each follow-up. A counterfactual challenged the map with a sequential timeline.

Consensus: persistent connected map plus sequential highlighting. Outer true-residual verification encloses correction PCG, which calls the multigrid V-cycle. Richardson smoothing exposes one shared physical feedback path. Only encoder → optical A → detector carries light. CPU/vector/control traffic remains electrical.

Aristotle: distinguish ownership and call/return; reuse hardware and label the active level and pre/post phase. Ada: preserve both stopping tests, actual recurrences, and the return to a fresh true residual. Feynman: name the current vector, what the detector returns, and the exact configured experiment.

Disagreement: a strict timeline is easier to read once but conceals iteration and recursion. Equally prominent spines may look like independent pipelines. The implementation uses explicit call and return arrows, one active node/path, and a live operation caption to resolve this.

Minority concern: long return paths can become dense. Secondary path labels appear during their active transfer, with primary branches permanently labeled. Mobile keeps the same connections with a vertical layout. Current x and reference x* are distinct; the reference never enters the solve.

Unresolved physical details: encoding, routing technology, signed representation and device timing remain unspecified. This is explicitly an ideal functional simulation. No physical implementation or speedup is claimed.

Result: `loop.html`; solver data/core copied verbatim from `index.html`. Existing lab and Python experiments unchanged. Verification: `verify-loop.cjs`, with actual captures in `loop-validation/`.
